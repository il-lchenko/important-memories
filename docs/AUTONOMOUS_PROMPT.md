## Правила
- Нейтральное позиционирование: не «свадебное» приложение. Полное ФИО владельца нигде публично не показывать (только «ImpoMento, самозанятый (НПД), ИНН 400707183208»; ФИО остаётся один раз в разделах реквизитов оферты, политики, согласия).
- Качество фото не трогать. Не логировать персональные данные и тексты постов. Вебхуки платежей идемпотентны.
- Новые Python-пакеты на VPS ставить нельзя (`rebuild-backend.sh` сломан): используй `cryptography`, Pillow, qrcode, aiosmtplib, boto3, ARQ. npm-пакеты — только лёгкие или dev для тестов.
- Bash: heredoc с кириллицей ломает парсер — скрипты правок пиши файлом (Write) и запускай python; сохраняй окончания строк CRLF/LF; в PowerShell нет `&&`.
- SSH к VPS: сначала `ssh impomento "echo ok"`, затем минимум соединений (`tar | ssh` вместо множества scp). Деплой только по рецептам из CLAUDE.md и памяти (бэкап `/opt/im/backup-postgres.sh` → tar app+alembic → `docker cp alembic` → `alembic upgrade head` → `/opt/im/deploy-backend.sh`; PWA: `tar -C dist . | ssh impomento "tar xf - -C /opt/im/guest-pwa/dist"`). Конфигурацию сервера (nginx, sshd, Docker, firewall) НЕ менять: находки по инфраструктуре только описывать в отчёте. Перед миграцией всегда бэкап БД. Если после деплоя прод сломан — вернуть предыдущую версию из git и разобраться.
- После каждого деплоя проверять прод-страницы (curl и headless) и записывать результат в память.
- Коммиты мелкими шагами и `git push origin main`; без force push; данные пользователей не удалять; миграции только обратимые или безопасные.
- Если упираешься в лимит токенов/времени: запиши в память точное состояние, оставь рабочее дерево рабочим (или wip-коммит в отдельной ветке).
